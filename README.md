# otel-playground
Local stack to test features of the opentelemetry collector. 

### endpoints
```
http://localhost:8000/                  base API endpoint  
http://localhost:8000/process/{item_id} dummy endpoint to mock kafka read + db write  
http://localhost:3000/                  Grafana LGTM frontend  
```

### data flow
```
app -> otel-collector -> lgtm stack
```

### otel-collector
The collector is a custom build (`otel-collector/`), since `adaptive_tail_sampling` isn't in the published contrib image yet. `builder-config.yaml` lists the included components; add any new component there (pinned to the same version) before using it in `otel-collector-config.yaml`, then rebuild with `docker compose up -d --build`.

Span metrics are emitted from the collector before sampling with `sampling_stage="pre"`, alongside the post-sampling metrics generated by the LGTM stack (no `sampling_stage` label):
```promql
sum by (sampling_stage, span_name) (rate(traces_spanmetrics_calls_total{span_kind="SPAN_KIND_SERVER"}[5m]))
```

### k6
`k6/load.js` generates steady traffic against the app to both `/` and `/process/{item_id}`.
```
k6 run k6/load.js
```
Values to tweak:
- `rate` / `timeUnit` per scenario — request rate (currently per minute)
- `DURATION` env var — test length (default `10m`), e.g. `k6 run -e DURATION=30m k6/load.js`
- `BASE_URL` env var — target host (default `http://localhost:8000`)
- `maxVUs` — raise if k6 warns about insufficient VUs (e.g. at higher rates)
